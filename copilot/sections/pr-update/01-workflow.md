# PR Update Workflow

Bring the PR branch up to date with a source branch while preserving the intent of both sides. The source branch defaults to `main`; if the user's agent request contains `main=<branch>`, use that exact branch name instead (for example, `main=develop` selects `develop`). Treat `main` as the parameter name, not a literal branch to merge when overridden. Reject an empty, invalid, or nonexistent branch and report the problem rather than falling back. Work in the existing repository and use its documented commands and conventions.

1. Identify the intended PR and verify its head repository, head branch, base repository, and base branch with `gh pr view` or the available GitHub tools. Resolve the source branch in the PR's base repository; it may differ from the PR's actual base branch. If the PR is ambiguous, the checkout is not its head branch, the source is the PR head, or the branch cannot be pushed to, stop and report what is needed. Never merge into the source branch or push to the PR's base branch.
2. Inspect `git status` and the existing branch history. Do not overwrite, stash, commit, or discard unrelated uncommitted work; stop if it would interfere or be included. Fetch the PR head, PR base branch, and selected source branch from their respective repositories. Verify the local PR branch contains the latest remote head; if it does not, stop rather than overwrite someone else's work. Record the PR head commit before merging.
3. Merge the freshly fetched source branch into the PR branch with `git merge --no-ff --no-commit <fetched-source-ref>`, without rebasing or force pushing. Resolve conflicts by examining the relevant code and both sides of each change, preserving the intended behavior of both. Do not blindly choose one side. If the correct resolution is unclear, stop and explain the conflict rather than guessing.
4. Review the PR changes relative to the updated base and the integration changes introduced by the merge. If `~/.local/share/agent-bob/find_related_tests.py` is installed, run `python3 ~/.local/share/agent-bob/find_related_tests.py --base <fetched-pr-base-ref> --before-merge <recorded-pr-head-commit>` after staging resolved conflicts. Its filename matches are candidates, not a complete dependency or coverage analysis; use project-specific test selection or coverage when available, and otherwise run a broader appropriate suite. If the helper is not installed, identify relevant tests using the repository's own tools and conventions. Run the existing tests relevant to the changed code and conflict resolutions, plus any required checks identified by the repository. Fix integration problems caused by combining the branches, and rerun affected checks. Do not silently skip failed or unavailable checks; report the exact blocker.
5. Once conflicts are resolved and required checks pass, complete the merge commit if needed and commit any additional fixes using repository conventions. Do not include unrelated changes. Verify the working tree and commits, then push the PR branch to its verified head repository using a normal, non-force push. If the remote has advanced or the push is rejected, do not overwrite it; report the situation.
6. Confirm the remote PR head includes the intended commits. Summarize the merge, conflict resolutions, fixes, checks, and push outcome. If blocked, clearly state what remains and do not claim the PR was updated.
